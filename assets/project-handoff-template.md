# Передача сайта следующей сессии

При разрешённом создании или существенной переработке сайта сохранить этот небольшой блок в AGENTS.md корня данного сайта. Не менять глобальный AGENTS.md, родительские проекты или настройки клиента. При существующем AGENTS.md добавить ограниченный блок, сохранив прежнее содержимое; если блок уже есть, обновить только его. При конфликте с действующими инструкциями не заменять их: указать конфликт и продолжить независимую часть. При read-only аудите не записывать инструкции без разрешения на изменения.

Блок относится только к работе над этим веб-проектом. Он не назначает новые права, не разрешает публикацию, не снимает пользовательские согласования и не фиксирует ожидаемый вердикт проверки.

```markdown
<!-- saitodel-project:start -->
## Продолжение работы над сайтом

Для создания, переработки, анимации и проверки этого сайта применять установленный навык «Сайтодел» и его references/integrated-skills.md. Найти навык штатно в текущей среде; если он недоступен, честно записать блокер. Не считать прошлую запись в SOURCES.md выполнением правил в новой сессии.

Перед самостоятельным аудитом/передачей заказчику прочитать из пакета Сайтодела vendor/vercel/AGENTS.md и command.md, TheGoat frontend-quality-auditor с audit-checklist.md и browser-inspection-workflow; visual-regression-lab при сравнении. Для анимации прочитать MotionSites и применимые рецепты. Общая инженерная проверка дополняет эти источники.

Восстановить исходный бриф, утверждённый дизайн, версию и прошлые ошибки из существующих документов проекта. Различать фактическую загрузку инструкции, применение, проверку исходников и проверку браузером. Не объявлять запуск инструмента или снимок экрана визуальной приёмкой; снимок должен быть просмотрен. Сохранять ошибки и повторные проверки отдельно.

При отказе шлюза разрешений остановить зависимое действие; не обходить отказ другим инструментом или отключением защиты. Небольшую правку текста выполнять в её границах без полного веб-аудита. Не публиковать сайт без действующего разрешения.
<!-- saitodel-project:end -->
```

В существующей записи работы указать, где сохранён этот блок, идентификатор/версию использованного пакета и реальные документы брифа. Не добавлять в блок ответы приёмочных тестов, искусственный процент или новые требования к продукту.
