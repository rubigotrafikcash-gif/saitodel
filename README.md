# Сайтодел 0.2.0

Навык для проектирования, создания, переработки и проверки сайтов в Work и Codex.
Четыре режима: новый сайт, переработка, аудит, мастер-промпт.
Основа — бриф, аудитория, смысл, CTA, выбранная концепция, адаптив и подтверждённый результат.

Для существенной работы координатор передаёт реализацию исполнителю, а приёмку — отдельному проверяющему.
Максимум три одновременно активных агента, включая координатора; первичная проверка и до двух циклов исправлений.
При недоступном делегировании работа продолжается последовательно, с явным отсутствием независимой приёмки.
Русский текст обрабатывается доступным «Словоделом», инженерные проверки — «Моим вайбкодером».

## Проверка и сборка

В корне репозитория, используя доступный Python 3.10+:

```text
python -m unittest discover -s tests -v
python scripts/package_release.py --check
python scripts/package_release.py --output-dir dist
```

В `dist/` появятся:

| Файл | Назначение |
| --- | --- |
| saitodel-skill-0.2.0.zip | Отдельный навык, одна папка saitodel |
| saitodel-plugin-0.2.0.zip | Переносимый плагин с единственным навыком saitodel |
| SHA256SUMS | Контрольные суммы обоих архивов |
| package-manifest.json | Состав архивов, версии и SHA-256 исходных файлов |

Проверенные архивы этой версии сохранены в [release/v0.2.0](release/v0.2.0). Для проверки контрольной суммы использовать SHA-256 из соседнего `SHA256SUMS`.

Сборка использует явный список файлов, не включает документы разработки, тесты, секреты и посторонние материалы.
В ZIP фиксированы порядок файлов, время и права; текст приводится к LF. Сжатие отключено для одинакового результата на разных версиях zlib.
Повторная сборка одинаковых исходников должна давать одинаковые байты архивов.
Проверки не обращаются в сеть и не устанавливают пакеты.

Frontmatter и `agents/openai.yaml` используют JSON-синтаксис, допустимый для YAML 1.2 mappings.
Это позволяет разбирать их стандартным JSON parser без отдельного YAML-пакета.
Проверяется конкретный контракт этой поставки; это не универсальный валидатор YAML или полный движок JSON Schema.

## Установка и обновление

Выбирать один способ обнаружения навыка на конкретной поверхности: отдельный навык или навык внутри плагина.
Перед обновлением найти существующий `saitodel`, сохранить его версию и обновлять его штатным механизмом.
Прежнюю установку не отключать и не удалять без отдельного поручения пользователя.
Пустой поиск не означает, что можно создать дубликат.

Для Work использовать поддерживаемый импорт или обновление существующего плагина из `saitodel-plugin-0.2.0.zip`.
Для standalone-навыка использовать `saitodel-skill-0.2.0.zip` через доступное управление навыками.
В Codex поддержка установки зависит от клиента; использовать его штатный каталог навыков или плагинов.
Идентичность аккаунтного плагина задаёт сервис при сохранении; имя пакета не заменяет backend ID.

Сборка архива и проверка текста не подтверждают установку.
После обновления отдельно проверить обнаружение и выполнение задания в Work и в целевом клиенте Codex.
Сеть и права текущей среды ранее блокировали установку; эти ограничения не обходятся упаковкой.
GitHub-публикация исходников, установка в аккаунт и публичный каталог OpenAI — разные этапы.

## Изменения 0.2.0

- Реализованы контракты трёх ролей, фиксация проверяемой версии, общий счётчик исправлений и ранняя остановка.
- Добавлен единый шаблон восстановления контекста.
- Разделены статусы сборки, визуального просмотра, сценариев и публикации.
- Исправлены устаревшие значения `policy.products`; новые ограничения продуктов не добавлены.
- Добавлены переносимый manifest, два варианта упаковки и проверки сборки.
- Сохранены четыре режима, основной процесс и согласованный регламент.

Пилот на сайте Натальи остаётся отдельной задачей после фиксации актуальных входов.
Синтетические проверки навыка не заменяют этот пилот или исследование с людьми.
Точные выполненные проверки и ограничения приведены в [отчёте версии 0.2.0](docs/releases/0.2.0/report.md).
Журнал `docs/installation-status-2026-11-08.md` и его свидетельства сохраняют состояние предыдущего этапа; они не подтверждают установку новой версии.
