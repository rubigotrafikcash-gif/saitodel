## Подтверждённые находки

### F1 — P0: главное действие ведёт на другой контакт

**Место:** `tests/fixtures/site.html:17`; требование — `tests/fixtures/brief.md:5`.

Кнопка «Обсудить задачу» имеет `href="https://t.me/another_example"`. В брифе утверждён `https://t.me/tochka_example`. Поэтому исходник направляет основное действие не по согласованному адресу. Ссылка в футере на строке 21 правильная, но не исправляет главный CTA.

**Точная предлагаемая замена, без внесения в сайт:**

```html
<!-- Было -->
<a class="cta" href="https://t.me/another_example">Обсудить задачу</a>
<!-- Должно быть -->
<a class="cta" href="https://t.me/tochka_example">Обсудить задачу</a>
```

**Повторная проверка после отдельно разрешённого исправления:** сравнить `href` всех целевых ссылок с брифом; в разрешённом браузерном сценарии активировать CTA и записать фактический переход. Не отправлять сообщения: контакт демонстрационный. Сейчас доказано только расхождение адресов в коде; существование и доступность контакта не проверялись.

### F2 — P0: мобильное правило принудительно расширяет содержимое

**Место:** `tests/fixtures/site.html:10`; связанные правила — строки 4, 7–8; требование mobile — `tests/fixtures/brief.md:11`.

```css
@media(max-width:600px){main{min-width:900px}}
```

При ширине viewport не более 600 CSS px контентная ширина `main` не может стать меньше 900 px. На строке 8 дополнительно заданы отступы по 24 px; в данном исходнике нет `box-sizing:border-box`. Следовательно, заданная внешняя ширина `main` составляет не менее 948 px. Это конфликтует с узким экраном и создаёт причину горизонтального переполнения.

Это подтверждённый дефект CSS, а не наблюдение рендера. Реальная обрезка текста, видимость кнопки и величина прокрутки в браузере не измерялись.

**Точное предлагаемое исправление, без внесения:** удалить правило `@media(max-width:600px){main{min-width:900px}}`, сохранив ограничение `max-width:1100px` и существующие отступы. Другие изменения адаптива определять по фактическому просмотру.

**Повторная проверка:** на узком и коротком экранах проверить отсутствие горизонтальной прокрутки, доступность смысла и CTA, меню в обоих состояниях. Предлагаемые размеры для будущей проверки этого аудита: 375×812 и 667×375; это план, а не выполненный просмотр и не ранее согласованные размеры.

### F3 — P1: меню нельзя закрыть штатным переключателем

**Место:** `tests/fixtures/site.html:23`; связанные элементы — строки 8, 12–13; требование — `tests/fixtures/brief.md:9`.

Обработчик всегда выполняет `classList.add('open')` и устанавливает `aria-expanded="true"`. В исходнике нет удаления класса, переключения состояния или отдельной кнопки закрытия. Повторное нажатие оставляет меню открытым, хотя бриф требует открытие и закрытие на той же странице. Якорные цели существуют на строках 18–21; утверждать, что все переходы меню сломаны, оснований нет.

**Предлагаемая замена обработчика, без внесения:**

```js
document.getElementById('menu').onclick = function () {
  const isOpen = document.getElementById('nav').classList.toggle('open');
  this.setAttribute('aria-expanded', String(isOpen));
};
```

**Повторная проверка:** открыть меню, закрыть той же кнопкой, открыть снова, пройти по каждому якорю, проверить доступность кнопки после перехода; повторить мышью, клавиатурой и на mobile. Проверить соответствие видимости `aria-expanded`. Сейчас проверена логика исходника, обработчик не исполнялся.
